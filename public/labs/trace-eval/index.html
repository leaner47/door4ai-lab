Trace 与 Eval 实验室

Agent 的一次运行是一棵 span 树。先把这棵树摊开看清楚每一步花了多少时间和钱，再用三种粒度给它打分，最后看怎么防止改坏、怎么在危险动作前拦住它。

00一条 trace 长什么样

任务：「比较北京和上海明天的天气，写一段 100 字以内的出行建议」。下面是这个 Agent 一次运行的 trace：最外层是整个任务，里面每一轮是一次模型调用（chat）加上它要求的工具调用（execute_tool），最后一道输出检查。左边是 span 树，可以折叠；右边是同一时间轴上的甘特图。点任何一行看它记录了什么。这条 trace 是页内示例数据（耗时、token 数为示意，天气为虚构），不是真实调用的记录；耗时、成本、字数等派生数字都由页面从这些数据算出来。

01时间和钱花在哪了

同一条 trace，按「模型调用 / 工具执行 / 检查 / 编排与等待」把墙钟时间切开：在每一个时刻，只要有模型调用在跑就记给模型，否则有工具在跑就记给工具，都没有就是框架自己的开销。成本只来自模型调用，按 token 数 × 单价算，单价可以改。

–墙钟时间
–模型调用占墙钟时间
–超时与重试多花的墙钟时间
–最慢的 span
–最贵的 span
–这次运行的总成本

单价默认值只是示例，按你用的那家改。多数时间花在模型调用上，最后一轮写摘要最慢也最贵：它要输出的 token 最多，而输出 token 一个一个生成、单价又高。关掉「并行执行」，工具时间从取最长那条线变成全部相加；一次超时会把整轮拖慢一秒，却不花一分钱，只看账单发现不了。

02三层 eval：看结果、看轨迹、看单步

同一个任务跑了 10 次，每次的工具调用和最终回答都不一样（页内示例数据）。三种判分都是页内真实执行的程序：结果检查最终回答里两城最高温是否和工具返回的一致、有没有说对哪边更暖、是否不超过 100 字；轨迹检查有没有调多余的工具、重复调用、漏调、轮数是否超限；单步检查每一次工具调用的参数是否合法。点一行看这次运行的全过程和判分理由。

–结果判分通过率
–轨迹判分通过率
–单步判分通过率
–结果与过程判分不一致的运行

分歧最大的两类：结果对、过程差（绕远路、重复调用，这次碰巧对了，但更慢更贵，下次可能就错了）；过程全对、结果错（数字抄错、结论说反，只有看最终输出的判分才抓得到）。三层各抓一类问题，缺哪层都会漏。

03LLM 裁判的偏差：模拟

开放式回答没有标准答案，常让另一个模型当裁判，在两个回答里挑更好的。这里模拟一个有偏差的裁判（模拟，不是真模型）：每次判断时，以概率 p 直接选排在前面的那个（位置偏好）；否则以概率 q 选更长的那个（长度偏好）；剩下的情况才真正比较质量，但也会看走眼，质量差距越小越容易判反。每组 200 对答案的真实优劣已知，长度和质量无关。重复 400 组，看准确率的分布。

校准办法：同一对答案交换顺序各判一次，两次选的是同一个才采纳；不一致说明这次判断靠不住，标为「没把握」，交给人或更强的裁判复核。

判一次的准确率交换判两次、只看一致结论的准确率

400 组模拟的准确率分布；虚线是解析期望值

–判一次：准确率
–交换判两次：结论一致的比例
–交换判两次：一致结论的准确率
–不一致记 0.5 分时的得分
–无偏裁判的准确率上限

只加位置偏好：被位置带偏的判断，交换顺序后两次会选不同的答案，于是被筛出去，留下来的一致结论准确率明显更高。但注意最后一个读数：如果把不一致都记 0.5 分，期望得分和只判一次完全一样（数学上恰好相等）。交换顺序不会让裁判变聪明，它的作用是告诉你哪些结论靠不住。把 q 也拉上去：长度偏好两次都选同一个更长的答案，交换顺序抓不到它，一致时的准确率跟着下降。长度偏差要靠别的办法：在评分标准里写明不看长度、按长度做回归校正，或抽一批人工标注核对裁判。

04回归测试：总分一样，不等于没变

同一套 30 道题的 eval 集（页内示例数据，按题型分 5 类），旧版本 v1 和新版本 v2 各跑一遍。上排是 v1，下排是 v2，绿色通过、红色失败；中间标出变化的题。点下排的格子可以翻转 v2 在这道题上的结果，看计数和显著性怎么变。

–总分 v1 → v2
–过 → 挂（退化）
–挂 → 过（修好）
–McNemar 精确检验 p 值

「改 prompt」两版都是 21 分，但有 5 道题从过变挂、5 道从挂变过：多步比较类退化，格式类变好。「换模型」总分从 21 涨到 25，安全类却从 4 掉到 2，这种退化往往是一票否决。McNemar 检验只看变了的题：变化的题少时，即使一边多几道，也很可能只是采样的运气。

05拦截：工具调用执行之前先过一道规则

Agent 要调工具时，循环在真正执行前先把这次调用交给一组规则判定：只读白名单直接放行；写操作要人确认；命中危险命令黑名单、读敏感路径、往外发密钥的直接拦截。下面每一条都是页内规则引擎实时判定的，切换策略看结论怎么变，也可以自己输入一条。

–放行
–需确认
–拦截

黑名单永远在最前面，不受策略影响；策略只决定写操作和不认识的工具怎么处理。规则只能拦住写得出来的模式：换个写法（rm -r -f、先 cd / 再删）就可能绕过，所以真实系统还要配沙箱、最小权限和人工确认，规则只是第一道。
