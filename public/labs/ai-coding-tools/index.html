AI 写代码实验室

AI 编程工具在你的项目里读文件、改文件、跑命令。下面把这个过程拆开：diff、测试和 Git 都在浏览器里真实计算和执行。

00一次 AI 改代码的全过程

任务是「给网页加一个深色模式按钮」。一步一步看 AI 做了什么：先读文件，再说计划，然后改文件、跑测试，测试失败后自己找原因再改，直到通过。这是一段预先写好的示意回放，但每一步的 diff 都是页面根据改前改后的文件真实算出来的。

注意第 9 步：AI 第一次写的代码是错的，而且它当时很自信。救场的不是它更聪明，而是「跑一下测试」这一步把错误暴露了出来，它才能看着报错再改。

01diff 怎么看

AI 改完代码，你要看的就是 diff：哪些行删了（红色、- 开头），哪些行加了（绿色、+ 开头），其余没变。页面用最长公共子序列（LCS）逐行比较左右两段文字。右边可以随便改，diff 立刻重算。

改一行在 diff 里是一红一绿两行：旧的删掉，新的加上。第三个例子里，你只让它改函数名，它却顺手改了别的地方，只有逐行看 diff 才发现得了。

02它能执行什么：权限

AI 想执行的每个动作，工具都会先按规则判断：自动执行、停下来问你，还是直接拒绝。下面是一套示意规则，和真实工具的细节不同，但思路一样：读最安全，改文件次之，跑命令、联网、删东西、推送到远端越来越需要你点头；项目外的危险操作在任何模式下都拒绝。

AI 想做的事规则认为它是结果

切换模式时，变的只有中间那一档；读文件永远自动，项目外的 rm -rf 永远拒绝。模式越放手，你越要靠 Git 存档和事后看 diff 兜底。

04需求写得好不好

  
同一个 AI，需求写得清楚，结果差别很大。一条好需求至少说清四件事：目标（要做成什么）、范围（改哪些文件、别动哪些）、约束（不许用什么、要保持什么）、验证（怎么算做完）。下面用一张检查清单按关键词给需求打分。这是页内规则，不是 AI 评分，只用来提醒你漏了哪一项。

关键词规则很粗糙，写满四项也不代表需求一定好；但缺了哪一项，AI 往往就在哪一项上自己猜。最常缺的是「验证」：不说怎么算做完，它就会在自认为做完时停下。
