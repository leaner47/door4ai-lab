Harness 实验室

模型只会输出文字，替它动手、替它管上下文、替它拦住危险动作的，是外面那层程序。下面五个实验都在页面里真实运行：一个迷你 harness、真实分词器计数、三种编辑格式的真解析器。

00拆掉一个部件，看任务在哪一步坏掉

任务：「把服务端口从 8080 改成 9090，并确保测试通过」。项目里有三个文件：config.json、app.js，以及一份七十多行的旧日志 server.log。模型用规则模拟，它的每一步决定都写死了；文件读写、搜索、测试、token 计数、窗口上限，都是页面里一个迷你 harness 真实在做。关掉某个部件，看会发生什么。

–任务结果（页面独立重跑测试）
–模型调用次数
–峰值输入 token
–server.log

注意看：每个部件坏掉的方式都不一样。没有循环，停在第一个 tool_use；没有工具执行，模型只会「说」怎么改；没有错误回填，第一次测试失败就中断；没有上下文管理，日志把窗口撑爆；没有权限确认，一个「顺手」的删除就真的执行了。

03同一处修改，三种编辑格式

改文件这件事，不同的 harness 让模型用不同的格式表达：整份重写、精确替换一段原文（str_replace）、带上下文的补丁（Codex 的 apply_patch）。下面三个框里是模型的输出，页面里有三个真解析器把它们应用到同一份 prices.py 上。框里的文字可以直接改；也可以点按钮注入模型常犯的错。

格式能否应用模型输出 token结果和预期一致

    
注意看：整份重写最贵，而且模型一偷懒写「其余不变」就会删掉代码，解析器却照样「成功」；str_replace 最严格，原文差一个空格或出现两次就拒绝；apply_patch 按上下文定位，还会逐级放宽（先精确、再忽略行尾空格、再忽略首尾空格），所以缩进写错一格也能打上去。哪种格式好用，取决于模型训练时练的是哪一种。

  






  
04Harness 每一轮拼出来的请求，和前缀缓存

  
每次调用模型前，harness 都要把系统提示、工具定义、记忆文件、历史和最新的工具结果按顺序拼成一个请求。拼法决定了两件事：前后两轮的请求有多长一段完全相同（这一段可以命中服务端的前缀缓存），以及每轮要付多少钱。下面对相邻两轮请求真实分词，再逐个 token 比较最长公共前缀。
