00M × N 变成 M + N

左边没有标准：每个应用要给每个工具单独写一份对接代码。右边有 MCP：每个应用实现一次 MCP client，每个工具实现一次 MCP server，中间是同一个「插口」。

–没有标准：要写的对接代码（M × N）
–有 MCP：client + server 的实现数（M + N）
–少写
–再多一个工具，要新写几份

M = 1 或 N = 1 时两边几乎一样，标准没什么用；应用和工具都多起来时，乘法和加法的差距才拉开。这和 USB、HTTP 这些标准的道理一样：谁先实现了插口，就能和另一边所有已经实现插口的东西直接连。

04谁来批准：权限与审批

  
server 能读写文件、跑命令、改远端仓库。规范要求 host 让人留在回路里：清楚展示有哪些工具、调用时有醒目提示、敏感操作要确认。确认太少有风险，太多会让人不看就点「允许」。选一个任务和一种策略，数一数这次要弹几次审批。
