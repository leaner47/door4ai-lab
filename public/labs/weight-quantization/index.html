00一个数在内存里的样子

浮点数把一串比特分成三段：符号（正负）、指数（小数点放在哪，决定范围）、尾数（有效数字，决定精度）。三种常见格式只是三段的位数不同。输入任意一个数，看它分别存成什么、存进去以后再读出来变成多少。

BF16 就是 FP32 截掉后 16 位尾数（再四舍五入）：指数还是 8 位，范围和 FP32 一样大，只是有效数字少了。FP16 指数只有 5 位，试试 70000：它装不下，变成 ∞；10⁻⁸ 太小，变成 0。训练时数值跨度大，所以大模型普遍用 BF16。

01量化一组数：吸附到整数格点上

整数格式（INT8、INT4）没有指数，只能表示等距的整数。量化就是给一组权重配一把尺子：scale 是相邻格点之间的距离，zero-point 是「0」对应第几格。每个权重只存它最近的格点编号，用的时候乘回 scale 还原。

q = round(x / scale) + zero　　x̂ = (q − zero) × scale

对称量化让 0 正好落在格点上、正负两边各一半（zero = 0，只需存 scale）；非对称量化按这组数的最小值到最大值铺格子，多存一个 zero，适合整组数偏向一边的情况。下面是 4096 个随机生成的权重（固定种子），换成「全为正」看两种方式的差别。

02粒度：多少个权重共用一把尺子

一个 scale 管多少个数，叫量化粒度。按张量：整个矩阵一个 scale；按通道：每个输出通道（矩阵的一行）一个；按组：每行再切成长度为 g 的小段，每段一个（GPTQ、AWQ 常用 g = 128）。粒度越细，每把尺子越贴合它管的那几个数，但 scale 本身也要存：每组一个 FP16 scale，平均每个权重多出 16 / g 位。

按张量时，幅度最大的那一行决定了所有行的 scale，幅度小的行大多被舍成 0。按通道解决了行与行之间的差别，但挡不住离群值：打开离群权重后，几乎每一行都分到一两个，每行的 scale 都被撑大，按通道的误差涨到接近按张量。按组时一个离群值只拖累同组的 127 个邻居。代价只是每个权重多存 0.125 位。

03真的做一次矩阵乘法

权重量化以后，要看的不是权重本身差多少，而是这一层的输出差多少。下面用一个 128 × 512 的权重矩阵乘 32 个输入向量（模拟 32 个 token），比较量化前后的输出。权重按组量化（g = 128，对称）。

大模型的激活（流过网络的中间向量）里有少数几个维度幅值特别大，这是 LLM.int8() 论文（Dettmers 等，2022）的观察。这些维度对应的那几列权重，误差会被放大。AWQ 的做法是：量化前先把这几列权重放大 s 倍（激活相应缩小 s 倍，乘积不变），让它们在格点上的相对误差变小；s 由一批校准数据的激活幅度决定。

04显存放不放得下，每秒能出几个 token

权重大小 = 参数量 × 每个参数的位数 ÷ 8。参数量按公开的模型结构逐层算出。生成阶段（decode）每出一个 token 都要把全部权重从显存读一遍，计算量却很小，所以速度上限约等于 显存带宽 ÷ 权重大小。权重压到 1/4，要读的字节就少到 1/4，上限提高约 4 倍。
