多头注意力实验室

把一个向量切成几十个头，各算各的注意力；再让这些头共享 K、V，换来更小的 KV cache。下面的数都在页面里真实计算，模型参数取自公开的 config。

00切头：同一个向量，分给 h 个头

每个 token 进注意力层时是一个 dmodel 维的向量。多头注意力并不是另外加了 h 套大矩阵，而是把 WQ、WK、WV 按列切成 h 块，每块投影出一个 dh = dmodel / h 维的小向量，交给一个头。拖动 h，看切法怎么变、参数量变不变。

–每个头的维度 dh
–每个头的 WQ 切片参数（d × dh）
–WQ、WK、WV、WO 合计（4d²）
–每个 token 要算的注意力分数行数

h 从 1 拖到 64，四个矩阵的参数合计一个都没变，算 QKᵀ 的乘法总数也没变（h 个头 × dh 维 = d 维）。变的只是：一次大的「相关性」计算，被拆成 h 次小的、互相独立的计算，每个头得到一张自己的注意力分布。

01多头：各看各的

同一句话，每个头算出一张自己的注意力热力图：第 i 行是第 i 个 token 把注意力分给前面哪些 token。前四个是构造示例：按规则给分数（只有对上的位置得 β 分，其余 0 分），再过 softmax，模仿研究者在训练好的模型里见到的几类头；后两个是随机初始化的头：token 向量、WQ、WK 都用固定种子随机生成，按 softmax(QKᵀ/√dh) 真算。句子可以改，token 之间用空格隔开。

行：提问的 token（Q）；列：被看的 token（K）。颜色越深权重越大，每行加起来等于 1。点上面的缩略图切换头

–当前头
–平均有效关注 token 数 1/Σw²
–被看得最多的 token（占全部权重）

六个头读的是同一句话，得到的却是六种完全不同的「相关性」：一个只看前一个 token，一个停在句首，一个把第二个「小猫」连回第一个「小猫」。单头注意力每行只能有一种分布，多头才能同时拿到这几种信息。随机头的分布糊成一片：分工不是设计出来的，是训练出来的。β 拖到 0，构造头也会变成平均分布。

02拼接，再乘 WO

每个头输出 dh 维，h 个头首尾拼接回 dmodel 维，再乘输出矩阵 WO。下面是一层注意力里每一步的形状（n 个 token），条的长短按元素个数的对数画。选「玩具」时，页面用 4 个 token、8 维、固定种子随机权重真算一遍。

–「拼接再乘 WO」与「各头乘自己那块 WO 再相加」的最大差
–玩具：h 个头与 h = 1 的输出最大差（参数完全相同）
–分数矩阵元素数 h × n²

第一个读数几乎为 0（只剩浮点舍入）：拼接后乘 WO，等于每个头乘 WO 里属于自己的那几行，再把结果加起来。所以 WO 的作用是把各头的发现混合、写回同一个向量。第二个读数说明：参数一模一样，只是切成几个头，算出的东西就不同了。Llama 的 K、V 那一行比 Q 窄，这就是后面要讲的 GQA。

03MHA、GQA、MQA：几个 Q 头共用一组 K、V

生成时，每个头的 K、V 都要缓存下来（KV cache）。如果让几个 Q 头共用同一组 K、V，要存的就少了。拖动 KV 头数 g：g = h 是标准多头（MHA），g = 1 是所有头共用一组（MQA），中间是分组（GQA）。同一种颜色的 Q 头共享同一组 K、V。

–方案
–每组 K、V 服务的 Q 头数
–KV cache 是 MHA 的
–采用这种配置的公开模型

Q 头一个都没少，每个头仍然有自己的「问题」；被合并的只是「被查询的标签和内容」。GQA 论文（Ainslie et al. 2023）把训练好的 MHA 模型改成 GQA 时，就是把同组内的 K、V 头取平均，再用约 5% 的预训练算力继续训练。

04KV cache 计算器

每个 token 在每一层要存 K 和 V 各 g × dh 个数，所以

每 token 字节数 = 2 × 层数 × KV 头数 × dh × 每个数的字节数

和 KV Cache 那一讲用的是同一个公式。选一个模型，或者改成自己的参数，比较三种方案。

–MHA：每 token
–GQA：每 token
–MQA：每 token
–GQA：KV cache 总量

Llama-3-70B 在 8K 上下文、bf16 下，按 GQA（8 个 KV 头）一条请求要 2.68 GB；如果它是 64 个 KV 头的 MHA，就是 21.5 GB，32 条并发就远超一张 80 GB 的卡。表里三个模型的 Q / KV 头数取自各自公开的 config.json；1 KB = 1000 B。

05带宽视角：每生成一个 token，都要把 KV cache 读一遍

逐个生成 token（decode）时，每一步都要把全部权重读一遍，再把每条请求的整段 KV cache 读一遍。这一步主要卡在显存带宽上，读的时间大致是

每步时间 ≈（权重字节数 + 并发数 × 上下文长度 × 每 token KV 字节数）÷ 显存带宽

MHAGQA（模型实际）MQA只读权重

横轴：上下文长度（对数坐标）；纵轴：每生成一步、只算读显存的时间

–读一遍权重
–GQA：读一遍 KV cache
–GQA：每条请求 token/s 上限
–同条件 MHA：每条请求 token/s 上限

上下文短时，时间几乎全花在读权重上，三条线挤在一起；上下文一长、并发一多，读 KV cache 的时间就超过读权重，MHA 的线先陡起来。这是只看带宽的理论下限：忽略计算、多卡通信，也不管放不放得下（放不下要多卡，看实验 04）。权重按 bf16、参数量按 config 算出；MHA、MQA 两条线是把同一个模型的 KV 头数改成 h 或 1 的假想版本。带宽：H100 SXM 3.35 TB/s、H100 PCIe 2.0 TB/s、RTX 4090 1.008 TB/s（NVIDIA 公开规格）。
