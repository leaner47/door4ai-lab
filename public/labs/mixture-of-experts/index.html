MoE 混合专家实验室

把一个 MLP 换成很多个专家，每个 token 只走其中几个。下面的路由、训练、蒙特卡洛和参数计算都在浏览器里真实进行。

00路由器：每个 token 去哪几个专家

路由器只是一个线性层：token 向量 x 乘 Wg，得到 E 个分数；softmax 变成概率；取最大的 k 个；这 k 个概率重新归一化，就是各专家输出的权重。

y = Σi ∈ top-k gi · 专家i(x)

同一类 token（两个数字、两个代码词）往往被送到相同的专家，这正是专家「分工」的来源。没被选中的专家，这个 token 一次乘法都不做：MLP 部分的计算量只有稠密版本的 k / E。

01负载均衡：别让所有 token 挤一个专家

路由器是和专家一起训练的。某个专家开始时稍微多拿到一些 token，它就学得更好，路由器就更爱选它，于是越来越挤，别的专家闲着没东西学。常用的对策是加一个辅助损失（Switch Transformer 的写法）：

Laux = α · E · Σi fi · Pi

fi 是这一批里分给专家 i 的 token 比例，Pi 是路由器给专家 i 的平均概率。两者都均匀时这一项最小（等于 α）。DeepSeek-V3 换了个办法：不加损失，给每个专家一个只用于挑选的偏置，负载高就调低、负载低就调高。

02容量因子：专家满了，多出来的 token 怎么办

训练时为了让每块 GPU 上的计算形状固定，每个专家在一批里最多处理 C 个 token：

C = 容量因子 × T · k / E

T 是这一批的 token 数。T · k / E 是完全均匀时每个专家该分到的数。先到先得，专家满了以后再来的分配被丢弃：这个 token 在这一层少算一个专家，只靠残差连接原样往下传。下面用蒙特卡洛模拟：E = 8、k = 2，专家的热门程度按 Zipf 分布（示例分布，偏斜 0 = 完全均匀）。

容量因子越大丢得越少，但每个专家都按 C 预留显存和计算，空槽就是白算；路由越偏斜，同样的容量因子丢得越多，所以容量因子和负载均衡是一起调的。DeepSeek-V3 靠负载均衡做到训练和推理都不丢 token；推理时多数实现也不设容量上限。

03总参数 vs 激活参数

一个 MoE 层有 E 个专家，每个 token 只用其中 k 个（再加上共享专家，所有 token 都过）。所以要区分两个数：总参数决定要准备多少显存；激活参数决定每个 token 要算多少。前向一次，每个参数大约是一次乘法加一次加法，每 token 计算量 ≈ 2 × 激活参数。

预设用的是公开 config 里的真实数字（来源见表）。改动 dmodel 时，注意力等其余参数按 dmodel² 缩放、embedding 按 dmodel 缩放（估算）。

算法：路由专家 = 层数 × E × 3 · dmodel · 专家中间维（SwiGLU 三个矩阵）；激活部分只算 k 个路由专家和共享专家；路由器 = dmodel × E，每层都算。Mixtral 和 DeepSeek-V3 的注意力、embedding 等由 config 逐项算出，和官方公布的总参数、激活参数对得上；DeepSeek-V4-Flash 的注意力结构较新，其余参数由官方总参数减去专家部分反推，再用它验算激活参数。权重显存不含 KV cache、激活值和量化的缩放因子。

04同样的激活参数：稠密模型 vs MoE

拿一个稠密模型，参数量正好等于 MoE 的激活参数。两者每个 token 的计算量一样，但显存和 decode 时读的权重不一样。decode 每一步都要把用到的权重从显存读一遍，带宽常常是瓶颈。batch 里只有 1 个 token 时，MoE 每层只读 k 个专家；batch 一大，不同 token 选的专家不同，要读的是它们的并集。

每个 token 按均匀路由独立地选 k 个不同专家时，某个专家没被某个 token 选中的概率是 (E − k) / E，所以 B 个 token 一共用到的专家数的期望是：

E · [ 1 − ((E − k) / E)B ]

稠密（参数 = MoE 激活参数）MoE

横轴：batch 里同时 decode 的 token 数（对数坐标）；纵轴：每一步要读的权重

batch = 1 时两者读的一样多，MoE 用激活参数的带宽换来了总参数的容量。batch 到 64，DeepSeek-V3 每层 256 个路由专家平均要用到 222 个，读的权重接近整个模型，而每个专家这一步平均只分到 2 个多 token，读进来的权重几乎没被复用。所以 MoE 推理通常用很大的 batch，并把专家分散到多块 GPU 上（专家并行：每块卡只放一部分专家，token 被发往存着它所选专家的那块卡）。每一步按读一遍全部非专家参数估算，输入 embedding 只查用到的行，没算在内；均匀路由是理想情况，真实路由偏斜时并集会小一些。
