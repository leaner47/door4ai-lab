分数是怎么算出来的、会怎么骗人、以及怎么给自己的任务做一套小评测。下面的 n-gram 模型、采样和对战都在浏览器里真实计算。

00困惑度：模型在多少个选项里犹豫

模型预测下一个 token 时给出一个概率分布。分布越集中，它越「确定」；越平，它越「困惑」。困惑度（perplexity）把这种困惑程度折算成一个直观的数：相当于在多少个等概率的选项里瞎猜。拖动「集中程度」，看熵和困惑度怎么变。

PPL = 2H，　H = −Σ pi log2 pi（bit）

β = 0 时分布完全均匀，PPL 正好等于 V；β 很大时几乎只剩一个选项，PPL 趋向 1。PPL 永远在 1 和 V 之间。语言模型报告的 PPL 就是把这个数在整段文本上取几何平均。

01在一段文本上比较几个模型的困惑度

这里在浏览器里训练四个字符级 n-gram 模型（看前 n−1 个字预测下一个字，加 k 平滑），用训练语料学，在另一段没见过的测试文本上算困惑度。两段文字都可以改。

训练困惑度随 n 变大一路下降，把平滑 k 调小，4-gram 几乎把语料背下来了；测试困惑度却往往在 2-gram 或 3-gram 最低，再大就上升，因为语料太小，长上下文大多没见过。只看训练集上的分数，会选错模型。

02同一道题多跑几次：pass@k 与采样方差

模型是采样生成的，同一道题跑两次可能一次对一次错。代码类 benchmark 用 pass@k：采 k 个答案，只要有一个通过就算过。公开的做法是每题采 n 次、数出通过数 c，再用无偏估计：

pass@k = 1 − C(n−c, k) / C(n, k)

下面用蒙特卡洛真实模拟：一个 Q 道题的 benchmark，每道题有自己的真实通过率（平均为 p），每次评测给每题采 n 个答案。

k 越大 pass@k 越高，这是允许多次尝试，不是模型变强。右图更要紧：同一个模型重复评测，分数自己就会晃好几个百分点；题数 Q 小、每题只采 1 次时晃得最厉害。榜单上差 1 分的两个模型，往往分不出高下。

03数据污染：测试题混进了训练集

benchmark 的题目公开在网上，很容易被爬进训练语料。这里用一个字符级 3-gram 模型演示：训练集 20 句，公开测试集 8 句，另留 8 句从没公开过的私有测试集。拖滑块，把公开测试集的一部分句子混进训练集，看两套测试集上的分数各怎么变。

混入的题越多，公开测试集上的分数越漂亮，私有测试集上几乎不动：模型没有变强，只是见过答案。这就是为什么新 benchmark 都强调「题目在模型训练截止日期之后出」，以及为什么要保留一套自己不公开的题。

04Arena 对战：Elo 怎么从一场场胜负里长出来

Chatbot Arena 这类榜单不出题，而是让两个匿名模型回答同一个 prompt，由人投票谁更好。设模型 A 对 B 的真实胜率为 p，模拟若干场对战，每场按 Elo 规则更新分数：

EA = 1 / (1 + 10(RB − RA)/400)，　RA ← RA + K(S − EA)

05给自己的任务建一套小 eval
