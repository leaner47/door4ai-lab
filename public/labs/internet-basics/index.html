网络实验室：我们是怎么连上互联网的

在浏览器里敲下一个网址，到网页出现，中间经过了你家路由器、运营商、国际出口、海底光缆和好几台 DNS 服务器。下面六个实验把这条路拆开来看：延迟按真实城市坐标和光在光纤里的速度算，路由用的是真实的最短路径算法。

00先记住四个比方

互联网上的东西几乎都可以套进「寄快递」这个比方：

IP 地址
= 门牌号

每台联网设备的地址，形如 104.21.5.8。网络只认这个号码，不认名字。

域名
= 店名

lab.door4ai.com 是给人记的名字，背后对应一个或几个 IP。

DNS
= 查号台

把名字翻译成 IP。每次打开网站，第一件事就是问它。

路由
= 快递分拣

数据被切成很多小包，每个路口的路由器看一眼目的地址，决定下一站交给谁。

01从你的手机到服务器，要走多远

选一个出发地和一台服务器。下面这串方块就是一个数据包要经过的环节，读数按两座城市的真实坐标算出直线距离，再除以光在光纤里的速度（约每毫秒 204 公里，是真空光速的三分之二）。

光缆不会走地图上的直线，要沿海岸线、绕过山脉、在城市之间中转，所以实际长度通常是直线的 1.3 到 2 倍。RTT（往返时间）是一个包去、再回来一趟的时间，ping 显示的就是它。从上海到洛杉矶，就算线路是笔直的，光走一个来回也要 100 毫秒以上，这是物理上限，花钱也买不到更快。

02IP 地址：门牌号不够用了怎么办

现在最常用的 IPv4 地址是 32 位二进制数，平时写成 4 段十进制，每段 0–255。32 位一共只能编出 232 ≈ 43 亿个地址，而全世界的手机、电脑、摄像头远不止这么多。解决办法是：一部分地址只在家里、公司里用（内网地址），出门时共用一个公网地址。

蓝色的位是这个地址段固定不变的「前缀」，剩下的位可以自由编号。192.168.x.x、10.x.x.x、172.16–31.x.x 是全世界通用的内网段：你家和邻居家可以同时有一台 192.168.1.23，互不冲突，因为它们从不直接出现在公网上。

NAT（地址转换）：你家路由器只从运营商那里拿到一个公网 IP（下面用示例地址 203.0.113.7）。家里每台设备出门时，路由器把发件人改成这个公网 IP，并换一个端口号记在表里；回信到达时再按表转回去。点几下试试：

这就是为什么家里的电脑「从外面连不进来」NAT 表里只有家里设备主动发出去的连接。外面有人主动敲门时，表里查不到这是给谁的，包就被丢掉。这顺带起到了一点防护作用，但也是远程访问家里服务器要额外折腾（端口转发、内网穿透）的原因。新一代的 IPv6 有 2128 个地址，每台设备都能分到公网地址，就不需要 NAT 了。

03DNS：把名字翻译成 IP

电脑不知道 lab.door4ai.com 在哪，要先查。查询是逐级问路：先看自己有没有记着，没有就问递归解析器（通常是运营商的 DNS，或你手动设的 8.8.8.8、114.114.114.114）。解析器从根服务器问起，一级一级问到这个域名的权威服务器，也就是真正管这个域名的那台。

各步耗时取的是典型值。答案里的 TTL（这里是 300 秒）是「这个答案可以记多久」，过期前所有人都直接用缓存，所以第二次访问几乎不花时间。也因为有缓存，改了 DNS 记录后，旧答案要过一会儿才会在各地消失。

这个网站的 DNS 就在 Cloudflaredoor4ai.com 的权威服务器是 Cloudflare 的两台服务器。实验里返回的是 Cloudflare 的地址（104.21 和 172.67 开头的段），而不是真正存网页的机器：打开了「代理」（橙色云朵）的记录，访问者先连到 Cloudflare 离他较近的机房，再由 Cloudflare 转给源站，源站的真实地址对外是隐藏的。

04路由：每个路口只管下一站

没有哪台路由器知道完整的路线。每台路由器只有一张路由表：「去某个目的地，交给哪个邻居」。数据包每到一站，那里的路由器查一次表，交给下一站，直到到达终点。下面这张图里的节点放在真实城市，连线的延迟按两城距离计算（绕远系数 1.5）。

点任意一条线把它「挖断」，看路由自动绕路；点一个节点，看它的路由表。上面终端里是 traceroute 的样子：它故意发出 TTL（最多跳几站）为 1、2、3…… 的包，每一站把 TTL 减 1，减到 0 时会回一封「超时」信，于是能一站一站地把路线问出来。真实互联网上，不同运营商之间用 BGP 协议互相告诉对方「哪些地址从我这里能到」，原理和这里一样：每个节点只知道邻居，合在一起就能到达全世界。

05DNS 污染：抢答的假答案

传统 DNS 查询是明文的 UDP 包，一路上的设备都能看到你查的是哪个域名。中国大陆的国际出入口处部署着防火长城（GFW）的设备，它们旁听经过的 DNS 查询，一旦发现查的是被封锁的域名，就立刻伪造一个回复发给你，里面是一个错误的 IP。它离你比真正的 DNS 服务器近，所以假答案先到；电脑只认第一个到达的答案，后到的真答案会被丢弃。这就是 DNS 污染。

污染、劫持、封锁的区别DNS 污染发生在路上：你问的服务器没问题，是中间设备抢答，所以把 DNS 换成 8.8.8.8 也躲不过。DNS 劫持是你用的 DNS 服务器自己给出假答案，比如有的运营商把输错的网址导到广告页。而 DNS 只是第一步：就算拿到了正确的 IP，连接仍可能被封 IP，或者在 HTTPS 握手时被识别出明文的域名（SNI）而阻断。所以只修好 DNS，通常还打不开被封锁的网站。

06打开一个网页，要来回几趟

拿到 IP 之后还没完。浏览器要先和服务器建立连接（TCP 握手），再协商加密（TLS 握手），然后才发出真正的请求。每一步都至少要一个来回，所以离服务器越远，这几个来回就越贵。拖一拖：

这是一个小页面的第一次请求，不算下载大文件的时间。看两件事：一是 RTT 从 20 拖到 200 时总时间接近翻 10 倍，因为来回次数是固定的；二是新协议（TLS 1.3、HTTP/3）的主要改进就是少跑几趟。CDN（比如本站用的 Cloudflare）的思路是把内容放到离你近的机房，让每一趟都变短。
