Token 实验室：一句话是怎么进出大模型的

模型看不见文字，只看得见一串整数。这六个实验先用真实的分词器切你的句子，再亲手训练一个 BPE，最后跟着这串整数走完模型内部的流水线，看它怎么变回下一个 token。

01亲手训练一个 BPE：每一步合并最常见的一对

上面那 20 万个 token 是怎么来的？BPE（Byte Pair Encoding）的训练只有一个动作，重复几十万次：

  1. 把语料里每个词拆成最小单位（这里用字母，真实分词器用字节）。
  2. 统计所有相邻片段对出现的次数，按词频加权。
  3. 把次数最多的那一对合并成一个新 token，记下这条规则，回到第 2 步。

左边的语料可以改，格式是每行「词 频次」。点「下一步」看合并怎么发生。

第一步合并的是 e + s（newest 6 次 + widest 3 次 = 9），接着 es + t → est。每合并一次，词表多一个 token，语料的总 token 数变少：词表越大，同样的文字用的 token 越少。一直合并下去，每个词最终都变成一个整块，这时 BPE 就退化成"整词词表"，见到新词就没办法了。所以真实训练会在词表达到预定大小时停下。

03中文为什么费 token：字节级 BPE

真实分词器不从"字"起步，而是从 UTF-8 字节起步：初始词表正好 256 个，任何语言、任何 emoji 都能表示。代价是一个汉字占 3 个字节，在合并出它之前要用 3 个 token。

合并 0 次时每个汉字是 3 个字节 token。最先合并的是标点和很多汉字共用的开头字节，接着出现完整的常用字（的、们、上），三五十次后开始出现整词（小猫、坐在、我们、模型），合并到最后「大语言模型」整个成了一个 token。途中还会冒出跨越两个汉字的奇怪碎片：BPE 只看频率，不懂汉字边界。语料里只出现一次的「分词」始终是碎片，根本没出现过的「垫」更不会被合并。所以中文在训练语料里占多少，直接决定中文用户要多花多少 token。

切到 Llama-3-70B 看每一站的参数条：参数几乎全在 FFN 和注意力里，Embedding 只占 1.5%。GPT-2 的输出投影和 Embedding 共用一个矩阵（权重共享），所以那一站参数为 0。

05自回归：一次只生成一个 token

模型每跑一遍只得到一个新 token。把它接到输入末尾，再跑一遍，才有下一个。第一遍要把整段输入一次性算完（Prefill），之后每遍只算新来的那一个（Decode），前面 token 的 K、V 存在 KV Cache 里直接复用。点「播放」看这个过程。

Prefill 那一遍并行算了全部输入，计算量最大；之后每遍只算 1 个 token，但 KV Cache 每步都在长。Llama-3-70B 每个 token 的 KV Cache 是 320 KB，一段 10 万 token 的对话就要约 31 GB 显存，这就是长上下文贵的原因。

06从概率到下一个 token：温度和 top-p

最后一站，模型给词表里每个 token 打一个分数（logit），softmax 把分数变成概率，再从概率里抽一个。抽法有两个旋钮：

  • 温度 T：先把 logit 除以 T 再 softmax。T < 1 让高分更高、分布更尖；T > 1 把分布摊平，更随机。
  • top-p：按概率从高到低累加，只保留累计到 p 为止的候选，其余直接排除。

真实 LLM 的 logits 来自 Transformer。这里用一个在下面这段语料上数出来的字级 3-gram 模型代替它（输入只看最后两个字），但从 logits 到采样这一段，计算和真模型完全一样。

温度拉到 0.1：最高的那根几乎占满，每次抽到同一个字，生成的文字会反复绕圈。温度拉到 2：长尾候选都冒出来，句子开始不通顺。top-p 设成 0.5，只有最前面几个候选能被抽中。聊天产品常用的组合是 T≈0.7、top-p≈0.9。

这个 3-gram 模型的训练语料

串起来

文本 → 分词器按合并规则切成 token 编号 → Embedding 查表变成向量 → L 层 Transformer（注意力让 token 互相交换信息，FFN 让每个 token 各自变换）→ 最后一个位置的向量投影成词表大小的 logits → 温度和 top-p 之后抽出一个 token → 接回输入，循环，直到抽到结束 token。

训练时走的是同一条路，只是不抽样：每个位置都去预测"下一个 token"，和真实答案比交叉熵，再反向传播更新所有参数。
