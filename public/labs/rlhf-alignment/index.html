从「两个回答，人选一个」出发，拟合分数、训练奖励模型、看它被钻空子、用 KL 拉住策略，再用 DPO 一步到位，最后把可验证奖励放进 Agent 环境。下面的拟合与优化都在浏览器里真实计算；偏好数据和打分函数是构造的示例。

00Bradley–Terry：分数差变成胜率

给每个回答一个分数 r。两个回答放在一起，人选 A 的概率只取决于分数差：

P(A 胜 B) = σ(rA − rB) = 1 / (1 + e−(rA − rB))

–P(A 胜 B)
–换算成 Elo 分差（× 400 / ln 10）

分差 0 时五五开；分差 1 时 73 : 27；分差 3 时 95 : 5。Arena 的 Elo 用的是同一条曲线，只是底换成 10、单位放大到 400 / ln 10 ≈ 173.7 倍。

反过来，手里只有一堆「谁赢了谁」，也能把每个回答的分数拟合出来：让观测到的胜负在这些分数下出现的概率最大（最大似然），用梯度上升一步步调。下面是同一个问题的 5 个回答，每两个之间比了 20 次（构造示例）。

01奖励模型：从成对偏好里学一个打分函数

真实的奖励模型是一个大模型，读入问题和回答，输出一个数。这里把它缩成最小的样子：每个回答用三个特征描述（有用度 h、长度 L（百字）、礼貌度 p），奖励模型 r = whh + wLL + wpp。训练目标就是 00 里的 Bradley–Terry 似然：

损失 = −平均 log σ(r(胜者) − r(败者))

偏好数据由一个模拟的「标注员」产生：他心里的分数是 3h + p + λ·L，按 Bradley–Terry 概率选，所以也会选错。λ 是他对长回答的一点偏爱。

λ 拖到 0，学到的长度权重也接近 0；标注员每百字只多给 0.3 分，奖励模型就老老实实学到约 0.3。奖励模型学的是标注员的全部口味，包括不该有的那部分。准确率只有七成多不是没训好：标注员自己就不一致，拿他心里的真实分数去猜，也只能猜对这么多。

02奖励黑客：分数一路涨，回答越来越差

现在拿上面那种奖励模型去训练策略。策略能调两个旋钮：认真程度 q（有用度 h = 1 − e−q，越往后越难提高）和长度 L。奖励模型给分 3h + wLL；但真实质量（构造的示例函数）在 300 字左右最好，再长就是注水：3h − 0.15(L − 3)2。策略只看得见奖励模型，沿它的梯度一步步爬（学习率 0.05）。

前几十步，认真程度和长度都在涨，两条线一起往上；过了最高点，有用度已经涨不动，长度却还在白拿分，奖励一路上升，真实质量掉头往下。把 wL 拖到 0，长度就不动了，两条线不再分叉。这就是评测那一讲的 Goodhart：奖励模型一旦成为优化目标，就不再是好的度量。

03KL 惩罚：一根绳子拉住策略

把策略简化成 5 种回答风格上的一个概率分布 π。参考模型（SFT 之后的模型）πref 原本的分布是 30% / 30% / 15% / 5% / 20%。奖励模型偏爱「超长堆砌」，给它 1.6 分，但它的真实质量只有 0.2（示例数字）。RLHF 的目标是：

最大化　Eπ[r] − β · KL(π ‖ πref)

下面每次拖动 β，页面都从 π = πref 出发，对 softmax 的 5 个 logit 做 1000 步（自然）梯度上升，再和解析解 π* ∝ πref · er/β 对一下。

β 很小，绳子松了，策略几乎全押在「超长堆砌」上，奖励最高、真实质量最低；β 很大，策略被拴在参考模型上，什么也没学。真实质量在中间某个 β 最好。β 不是越大越安全，也不是越小越强，是一个要调的旋钮。

06放进 Agent 环境：奖励怎么设计，模型就学成什么样

把可验证奖励用到多步任务上：每道题是一个沙箱（代码仓库、几个工具、一个提交动作），模型自己跑完一整条轨迹，最后按测试结果给 0 或 1。下面的「模型」是一个只在三种做法之间选择的策略，每种做法的成功率是构造的示例；采样、组内优势、策略梯度更新都是真实计算。每组对同一道题采样 G 条轨迹，第 i 条的优势是

\[ A_i = \frac{r_i - \operatorname{mean}(r_1,\dots,r_G)}{\operatorname{std}(r_1,\dots,r_G) + \varepsilon} \]

轨迹里只有模型自己写的 token 乘上 \(A_i\) 进入损失；工具返回的内容是环境给的，不计入。
