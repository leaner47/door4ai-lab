## 一句话版本

**Git 是一个软件，GitHub 是一个网站。** Git 装在你的电脑上，记下一个文件夹的每一次改动，随时可以回到任何一个过去的版本，不联网也能用。GitHub 在云端保存 Git 仓库，再加上多人协作的功能：同步、在线审阅（Pull Request）、记录问题（Issues）、自动测试和部署（Actions）。

## 实验里讲了什么

1. **三个区域。** 工作区是你正在编辑的文件，暂存区是「下次提交要带上的改动」，仓库里是一串提交，每个提交都是整个项目在某一刻的快照。`git add` 决定哪些改动进暂存区，`git commit` 把它们打包成一个快照。实验里的 `git status` 输出和真实 Git 一致；点任何一个旧提交，可以看到项目当时的样子。
2. **哈希指纹。** 提交编号（如 `a3f9c21`）是 SHA-1 哈希的前 7 位。实验里算的就是 Git 真正存文件时用的哈希，和 `git hash-object` 的结果完全一样：改一个字符，40 位几乎全变。每个提交还记着上一个提交的哈希，所以改动一个旧提交，它之后的每个哈希都会变。
3. **分支与合并。** 分支只是一张贴在提交上的标签。在分支上试新功能不会影响 main。合并时，如果 main 期间没动过，Git 只是把标签挪过去（fast-forward）；两边都有新提交，就生成一个有两个父提交的合并提交。
4. **push 与 pull。** 你的电脑、GitHub、同学的电脑是三份独立的副本。实验会重现最常见的报错：GitHub 上有你本地没有的提交时，`git push` 被拒绝，要先 `git pull`。
5. **Pull Request。** 开分支 → 提交 → 推送分支 → 开 PR → 同事审阅 → 补提交 → 合并 → 删分支，一步一步看提交图和 PR 页面怎么变化。

## 为什么放在这里

后面的课程会越来越多地让 AI 直接改代码（Claude Code、Codex 都会自己执行 `git commit`）。看懂提交、分支和 diff，才能放心地让 AI 动手，出了问题也知道怎么退回去。这个课程网站本身就是一个 GitHub 仓库：每次 push 到 main，Cloudflare 自动重新发布。
