01对话模板拼装器

调用 API 时发的是一个消息列表：系统提示、用户消息，多轮对话时还有模型之前的回答。模型不认识「消息」，服务端先用对话模板把它们拼成一串 token：每条消息前后加上特殊 token，标出谁在说话、哪里结束，最后补上「助手开始说话」的标记，让模型从那里接着写。

改下面的文字，或者换一种模板，看拼出来的完整字符串和每一段占多少 token。特殊 token（蓝底）每个就是 1 个 token；其余文字用 o200k 分词器（GPT-4o 用的那个）逐段真实计数，Qwen 和 Llama 自己的分词器数出来会略有不同。

02prompt 检查清单

一个系统提示好不好，最终要在测试题上跑了才知道（实验 05）。但有些缺漏一眼就能查出来：有没有说清角色和结果给谁用，有没有写任务、规则和输出格式，有没有示例，外来文字有没有用标签圈起来，有没有只说「不要」不说「要」，有没有前后打架的要求。

贴一段系统提示进来，下面按页内写好的规则逐项检查。这是页内规则打分，不是 AI 评分：规则只看有没有出现某类写法，不判断写得对不对。

    –通过的检查项

    –否定说法的次数

    换到「满是不要」：全是禁止，没有一句说该怎么做。换到「前后打架」：同时要求简短和详细，模型只能二选一。

    03少样本的偏差（示意）

    要分的评论是「耳机本身没问题，就是客服回消息太慢了」，按规则它是中评。只看评论本身时，设模型给三个标签的分数是 \(s = (0.9,\ 1.2,\ 0.7)\)（好评、中评、差评），中评最高。

    放了示例之后，按 Zhao 等（2021）发现的两种偏差，给每个标签的分数加两项：示例里这个标签占的比例乘 \(\alpha\)（多数偏差），以及最后一个示例是不是这个标签，是就加 \(\beta\)（最近偏差）：

    \[ \begin{aligned} z_c = s_c &+ \alpha \cdot \frac{n_c}{k} \\ &+ \beta \cdot [\,\text{最后一个示例是 } c\,] \end{aligned} \]

    再用 softmax 变成概率。下面点按钮往示例序列里追加示例，点序列里的示例可以删掉它，「打乱」随机换顺序。这是示意模型，分数和偏差强度是编的，偏差的方向来自论文。

    试试先放「差评、中评、好评」，再点几次「打乱」：示例一个没换，答案跟着最后一个示例走。三类数量不均衡时，示例里多的那类会把答案往自己那边拉。

      05两版 prompt 的对比表
      
  
      改了 prompt 之后，要在同一组测试题上把新旧两版都跑一遍，逐题比较。下表是 10 道题：v1 只有一句任务和输出格式，v2 是文章里四块的系统提示。结果是示例数据，为了演示怎么读而编的，不是真实模型的运行结果。点 v1、v2 两列的格子可以改对错。
      
  
      读数里的标准误是 \(\sqrt{\hat p\,(1-\hat p)/n}\)；McNemar 检验只看两版结果不同的题：如果两版一样好，每道这样的题朝哪边翻都是一半对一半，p 值是「至少这么偏」的概率。「题目放大」把每道题复制成几道（同样的比例、更多的题），看同样的结果在多少题上才算靠得住。
